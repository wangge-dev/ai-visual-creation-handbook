# 维护手册

## 内容改在哪里

正文与完整模板在docs/；仓库、工具、平台与发现来源在data/。资源ID由正文resource_ids引用。资源卡、导航、网站与下载件自动生成。目录描述完整建设范围，正文与实操状态分别记录。

## 一次维护

1. 运行`npm run maintain -- --discover --limit 3`，轮转读取任务检索词及重点仓库。
2. 阅读`.maintenance/latest.json`中的新增、变化、失败、待续页和影响页面。对高价值候选运行`npm run maintain -- --repo owner/repo`取得README与文件树。
3. 阅读实际来源。候选的用途、输入、输出、许可和依赖明确后，独立编写资料卡；只改来源支持的事实。版本提交活跃不等于教程已失效。
4. 用resource_ids定位受影响正文，修订具体步骤或限制，更新CHANGELOG.md及maintenance/reviews/。
5. 运行相关测试及`npm run build`，查看受影响页面、完整模板和必要导出。常规修订用普通Git提交发布；未确认变化只留待核。

## 失败与日期

每个来源失败独立记录，其他来源继续；失败查询保留成功页位置，下轮到该查询时重试。多页搜索记录next_page和未完范围，最多检索GitHub搜索允许的范围，不宣称全量。

运行时间记录在本地报告；来源核对日记录在经过人工内容复核的资料卡；正文修改日记录在正文。无有效变化不刷新公開日期。首次读取标first_observations，避免当成仓库刚发生变化。

公开运行无需凭证但可能限流；可使用环境变量GITHUB_TOKEN或本机已配置的Git凭证，凭证只在内存中发给api.github.com，不进输出、日志或仓库。不会执行外部README／Skill命令。

## 周期与边界

计划每周一集中维护，月内第一次周维护增加平台、依赖与来源健康复核。同一入口手动试跑后再启用周期任务；具体启用状态见本机运行记录。电脑与Codex应用运行时才能访问本地文件。

独立提示词库与既有来源采集器维持原维护流程。本仓库复用链接和只读来源记录，原件仍留原资料池。内部候选、采集原响应和本机配置不公开。

待补真实案例见maintenance/backlog.md。平台实际粘贴、PS操作、图像与视频生成需要另外执行，源文件与构建成功不能代替这些结果。
