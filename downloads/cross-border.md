# 跨境出图：从商品事实到渠道交付

一套跨境图片先固定商品事实，再按市场、图片位置和语言安排表达。Amazon主图负责真实识别，副图和A+负责解释；Shopify还要适配主题裁切，Shopee需要按市场整理封面、规格与变体。先完成一条商品链路，再扩大SKU。

## 这次练习准备什么

以下所有DN01、DN02名称和参数均为虚构练习数据，用来示范怎么填写任务；正式商品须替换为自己的真实记录。练习未附商品照片，也未执行生图。

| 字段 | DN01练习数据 |
| --- | --- |
| 商品 | 带盖桌面收纳盒，虚构练习名DeskNest |
| 外尺寸 | 长220 × 宽150 × 高120 mm |
| 颜色与材质 | 白色；ABS，练习设定 |
| 已知结构 | 一个可拆隔板、一个盖子 |
| 发货内容 | 盒体1、盖子1、隔板1；不包括场景道具 |
| 获准场景 | 书桌收纳文具 |
| 未知项 | 容积、耐温、承重、防水、食品接触、认证、回收属性均未知 |
| 实拍需求 | 正面、顶部、开盖、隔板、侧面；未提供的角度不凭空补 |

把真实素材按“对象照片、风格参考、准确文案、尺寸记录”四类整理。参考图只借用背景或布局；商品照片承担外观依据，规格来自记录。复制[P09跨境简报](https://wangge-dev.github.io/ai-visual-creation-handbook/prompts/P09)，先生成渠道任务表。

## 第1步：建立渠道矩阵

| 任务 | 母版职责 | 后续动作 |
| --- | --- | --- |
| Amazon US主图 | 只展示实际发货商品 | 检查类目规则、白底、占幅与实际像素 |
| Amazon US副图 | 场景、结构、尺寸、配件、使用 | 每张只解决一个买家问题 |
| Amazon A+ | 按实际模块组织图像与文字 | 用模块提示确定尺寸，手机预览 |
| Shopify商品媒体 | 多角度与细节解释 | 排顺序、写alt text、看主题裁切 |
| Shopify首页横幅 | 主题表达与商品引导 | 桌面和手机分别重排构图 |
| Shopee SG | 清晰封面、规格与变体 | 按当地后台检查上传参数 |

这张表是练习任务分配，不规定每个渠道必须上传固定张数。[平台资料卡](https://wangge-dev.github.io/ai-visual-creation-handbook/resources/)集中保留官方来源与适用范围；1024、2048等数字要区分官方建议、当前限制和练习母版。

## 第2步：先做一张真实主体母版

选清晰正面或45度实拍，在图层软件抠出主体。原照片、蒙版和商品层保留，记录允许修改的是背景、接触阴影和文案层。没有实拍时可以继续准备简报与版式，不把概念图写成正式商品图。

先按[Amazon主图教程](https://wangge-dev.github.io/ai-visual-creation-handbook/ecommerce/amazon-listing)完成白底任务，再用同一真实主体建立场景图。模型容易改商品时，只生成背景，在PS／Krita里合成真实主体。检查商品颜色、盖子、隔板与数量后，再扩展其他图。

## 第3步：按位置组织信息

副图不要每张重复同一句卖点。DN01可分成桌面场景、开盖结构、外尺寸、发货内容和使用顺序；“耐高温”“大容量”等未知事实不填。使用[P11副图分工](https://wangge-dev.github.io/ai-visual-creation-handbook/prompts/P11)获得逐张构图和完整任务词。

[A+教程](https://wangge-dev.github.io/ai-visual-creation-handbook/ecommerce/amazon-a-plus)把结构、规格和使用拆模块；[Shopify产品页](https://wangge-dev.github.io/ai-visual-creation-handbook/ecommerce/shopify-product)把相同事实整理成媒体序列；[Shopee教程](https://wangge-dev.github.io/ai-visual-creation-handbook/ecommerce/shopee-localization)明确市场与变体。准确文字优先用可编辑图层，不反复让整图模型改小字。

## 第4步：本地化、SKU与交付

先做好一份事实母表，再制作英文或日文版本。场景和表达可调整，商品尺寸、配件和功能不能随市场变化。使用[本地化与单位教程](https://wangge-dev.github.io/ai-visual-creation-handbook/ecommerce/localization)，再按[SKU交付教程](https://wangge-dev.github.io/ai-visual-creation-handbook/ecommerce/cross-border-sku-delivery)建立文件清单。

最终交付包含：任务表、准确文案、图片、源文件状态、实际像素、检查结果和未完成项。网页上传成功、文字准确、源文件可编辑分别检查。完整流程还可以放进[三类画布](https://wangge-dev.github.io/ai-visual-creation-handbook/ecommerce/cross-border-canvas)。

## 最小完成标准

一张图能对照真实商品核验；对应渠道位置明确；准确文字与单位无误；文件能打开且裁切适用。规划、生成、合成、源文件与后台上传各自记录完成状态。当前内容完成的是教程和模板，不是新商品实操结果。

# Amazon主图与副图：一步一步制作

本教程以DN01普通收纳盒为练习，面向Amazon US商品页。先核对具体类目和图片位置；服饰等有特殊要求的类目不能直接照搬。案例数据见[总流程](https://wangge-dev.github.io/ai-visual-creation-handbook/ecommerce/cross-border)。

## 先准备素材和规格记录

准备真实商品正面、开盖、细节照片，发货清单与外尺寸。记录“主图／副图、站点、类目、当前官方出处、核对日期、导出要求”。Amazon公开摄影指南提供白底、主体占幅和文件建议；它是公开指导，不替代当前类目后台规则。[官方摄影指南](https://sell.amazon.com/blog/product-photos)。

练习母版选2000×2000像素方图，属于本教程的制作建议。生成工具只支持其他像素时记录实际结果，再通过合成或裁切完成目标版式；放大不能补回不存在的真实细节。

## 第1步：做白底主图

1. 挑一张能看清完整盒体、盖子与发货内容的实拍；主体必须来自这一张真实素材。
2. 抠图后放入纯白画布，避免灰色渐变、纹理、装饰物与宣传标签。真实商品自身标识保留。
3. 主体放大到清晰可识别、四边不被裁切；用当前规则检查占幅，不能只看模型写了什么。
4. 对照原照片检查边缘、颜色、透明或反光区域。阴影不改变商品结构，不画出不存在的配件。
5. 使用[P10白底主图](https://wangge-dev.github.io/ai-visual-creation-handbook/prompts/P10)；如果模型保不住主体，就只做背景／处理方案，再用真实商品层合成。

DN01的文具是场景道具，不出现在主图发货展示中。没有清晰照片时先补拍，不能从风格图借一个相似商品。

## 第2步：规划副图职责

| 图片 | DN01练习任务 | 要补的素材 |
| --- | --- | --- |
| 场景 | 放在书桌上说明用途 | 真实主体＋获准文具道具 |
| 结构 | 开盖与可拆隔板 | 开盖、隔板实拍 |
| 尺寸 | 长宽高与单位 | 外尺寸记录；不能画内尺寸 |
| 发货 | 盒体、盖子、隔板数量 | 包装／配件清单及照片 |
| 使用 | 打开、放文具、合盖 | 实际动作或可信步骤依据 |

用[P11](https://wangge-dev.github.io/ai-visual-creation-handbook/prompts/P11)先生成逐张简报，不一次生成完整拼贴。照片未显示的背面或结构列待补；准确短文案独立排版。尺寸图使用[P18](https://wangge-dev.github.io/ai-visual-creation-handbook/prompts/P18)，不要套用服装通用尺码表。

## 第3步：导出与实际页面检查

主图、副图单独命名并按顺序排列。核对实际像素、格式、体积、主体与文字；看缩略图是否一眼辨认。上传后查看桌面与手机实际商品页、裁切和变体对应，后台结果留记录。

本教程尚未进行Amazon后台上传。某个脚本给出PASS只能说明它检查了指定字段，不能代替商品真实性、类目要求和平台审核。

# Amazon A+：把图片改成模块化说明

A+先选择当前账户可用的模块，再安排图和文字。把国内长详情页缩成一张图片，会让文字、模块和手机阅读一起失控。用DN01练习时，品牌故事只写真实提供的内容，虚构练习名不补创始人经历。

## 第1步：记录实际模块

打开当前A+编辑器，登记模块名称、图像槽位、推荐／要求像素、文字字段与手机预览。不将某个常见宽度写成所有Basic或Premium模块的统一尺寸。账户可用模块未提供时，可以先完成模块内容方案，导出像素列待填。

Amazon公开设计指南建议图文合理搭配、遵守模块尺寸，并强调手机阅读时的文字处理。[官方A+设计指南](https://sell.amazon.com/blog/a-plus-content-design-guide)。本教程只采用任务组织方法，不把文章中的示例当作你的账户能力。

## 第2步：给每个模块一个问题

| 内容单元 | 买家问题 | 练习内容与输入 |
| --- | --- | --- |
| 开头 | 这是什么、在哪里用 | DN01实拍与书桌场景 |
| 结构 | 怎么安排文具 | 开盖、可拆隔板实拍 |
| 规格 | 是否能放到桌面 | 220×150×120 mm外尺寸记录 |
| 使用 | 怎么打开和摆放 | 经核实的操作步骤 |
| 配件 | 实际收到什么 | 盒体1、盖子1、隔板1 |

这是五个内容单元，不要求必须使用五个模块。根据实际模块合并或拆开；不为了填满模块捏造其他型号、测评或性能。

## 第3步：逐模块制作

复制[P12 A+规划](https://wangge-dev.github.io/ai-visual-creation-handbook/prompts/P12)，得到各模块的图片简报、准确文案和缺失项。先做一张场景底图，再做结构与尺寸。把文字放在支持的原生字段或独立排版层；长说明优先用文本模块。

对比图只比较真实存在、已提供参数的型号。当前练习只给DN01时，不编造竞品和第二型号。热点、轮播、视频等只有实际模块支持才纳入交付。

## 第4步：检查与返工

逐模块检查图像裁切、字体、单位、发货内容和事实依据，再看桌面与手机预览。文字错误只改文字字段／图层；结构错误回到对应实拍与合成步骤；尺寸不合适重新排版该模块。

交付保留模块清单、独立图片、准确文字、源文件和预览状态。没有进入账户编辑器时，只报告“模块内容方案已完成”，不报告“已上线”或“已通过审核”。

# Shopify产品页：媒体顺序与准确文字

Shopify产品媒体承担商品解释，主题决定显示方式。先做一套商品媒体，再看产品页、集合页和手机；不要把首页横幅的上传限制直接套到产品图片。

## 第1步：分清上传入口

当前官方产品媒体文档列出产品／集合图片的尺寸与体积要求，推荐方图可用2048×2048；具体显示取决于主题。[产品媒体说明](https://help.shopify.com/en/manual/products/product-media/product-media-types)。本教程把2048方图作为练习母版，不宣称它适用于所有图片区块。

通用图片说明另列上传限制，还注明产品图片存在不同限制。核对时记录是产品媒体、集合图片，还是主题中的首页／幻灯片素材。[通用图片说明](https://help.shopify.com/en/manual/online-store/images/theme-images)。

## 第2步：安排图片顺序

DN01可以按“整体识别→开盖结构→书桌场景→尺寸→发货内容→使用”排列。这是教程示范顺序，张数和第一张选择按你的买家任务与主题检查。商品主体在整套里保持颜色、结构和比例。

使用[P13产品媒体](https://wangge-dev.github.io/ai-visual-creation-handbook/prompts/P13)生成逐张任务、准确短文案和alt text。第一张缩略图要能识别商品；细节图需要真实近照，不能用生成的隐藏结构充数。

## 第3步：把文字放到合适的位置

较长规格和使用说明放在产品文本、主题区块或可编辑表格中。图片中文字只保留必要的尺寸或结构标签，手机缩小后仍能看清。产品变体使用各自真实照片，不能把白色版本重染成未经确认的灰色SKU。

alt text描述图片实际内容，不堆关键词。示例：“White DeskNest DN01 desk organizer with lid and one removable divider.”这句话仅用于虚构练习；正式内容依照实际商品和图中对象填写。[官方alt text说明](https://help.shopify.com/en/manual/products/product-media/add-alt-text)。

## 第4步：实际主题预览

在产品页与集合页检查：首图缩略、同排图片的比例、放大查看、图文区块顺序、变体切换、手机裁切和读取。准确的母版在主题里仍可能被裁掉，调整图片焦点或重新安排构图。

交付包括媒体顺序、各张图片、准确文案、alt text表和主题预览记录。尚未进入实际Shopify商店时，不把本地HTML预览写成主题验证完成。

# Shopify横幅：桌面与手机分别排版

先确定具体主题、区块和文字呈现方式。同一个背景在桌面留白充足，到了手机可能只剩商品一角；所以横幅不能只做等比缩小。

## 第1步：记录区块条件

登记区块是否支持桌面／手机不同素材，图片焦点、覆盖文字、按钮与容器高度如何设置。拿当前主题的实际预览判断；“所有Shopify横幅都用同一个尺寸”不是可靠的交付要求。

练习先做桌面2400×1200、手机1200×1600两个构图稿，均是本教程的设计建议，不是平台统一规格。实际区块不支持双素材时，制作可兼容裁切的母版并记录取舍。

## 第2步：准备两份构图简报

| 版本 | DN01练习构图 | 检查重点 |
| --- | --- | --- |
| 桌面 | 商品在右侧，左侧留给原生标题和按钮 | 完整主体、文字区对比与留白 |
| 手机 | 商品放在中下部，上方留给短标题 | 主体不被裁、按钮不遮关键结构 |

使用[P14双尺寸横幅](https://wangge-dev.github.io/ai-visual-creation-handbook/prompts/P14)。底图先不画标题、按钮和促销信息；准确文字交给主题或图层排版。英文示例“Make room for everyday essentials”是创作文案，不是“节省多少空间”的事实承诺。

## 第3步：先做底图再排版

商品来自真实实拍，桌面道具只作背景，避免暗示随商品发货。匹配光向与接触阴影，不改变盒体。手机稿重新摆主体和背景，不从桌面稿中心裁一刀交付。

必要时用[P06](https://wangge-dev.github.io/ai-visual-creation-handbook/prompts/P06)只调整背景或留白。生成工具如果只支持近似比例，先保存实际底图，再在图层画布里裁切或扩背景，报告最终实际像素。

## 第4步：四个场景预览

检查桌面宽屏、平板、手机和集合／首页实际位置。文字与按钮另有自己的布局条件，不能只看图片文件。导出文件、源文件和已预览区块分别列清楚；“PNG已完成”不等于“主题已配置”。

上传限制与色彩处理见[Shopify官方图片说明](https://help.shopify.com/en/manual/online-store/images/theme-images)。没有做真实商店预览时保留待验证状态。

# Shopee SG：封面、规格与变体套图

本页以新加坡市场英文商品页为练习。其他市场的语言、位置和上传提示需另查。Shopee SG公开指导建议清晰实际商品、干净封面、规格和使用信息；这些是该页面的指导，不是所有市场、店铺类型的统一硬性规则。[SG官方商品页指导](https://ads.shopee.sg/learn/faq/520/172)。

## 第1步：整理当地任务

记录市场SG、商品DN01、页面位置、语言、变体、上传尺寸／体积要求、官方出处与核对时间。当前后台参数未提供时，先做可重排的方形母版；示范采用2000方图，属于制作建议。

官方SG指导建议至少1024×1024的方图及纯白封面。本页不据此填写全站图片数量、全部接口大小或其他地区限制。店铺特殊规范、上传提示和类目条件另核对。

## 第2步：给套图分工

1. 封面：白底真实商品，清晰展示盒体与盖子，不叠无依据的促销标识。
2. 结构：开盖和可拆隔板，用实际照片和准确短标签。
3. 尺寸：220×150×120 mm外尺寸，标明长、宽、高；不把单位换算当测量。
4. 配件：盒体1、盖子1、隔板1，文具道具不是套装内容。
5. 场景：获准书桌使用情境，商品大小关系与光影可信。
6. 变体：只展示清单中真实存在的SKU，颜色和型号不自行增加。

这些是示范任务，实际上传张数以当地界面和商品需求安排。复制[P15 Shopee SG套图](https://wangge-dev.github.io/ai-visual-creation-handbook/prompts/P15)，先输出任务表，再逐张处理。

## 第3步：英文表达与变体检查

# 跨境本地化：英文、日文、单位与准确文字

先做事实对照，再调整表达和版式。同一个参数翻译后仍是同一个参数；市场不同并不允许改变商品材质、尺寸、配件或性能。

## 第1步：建立词表与事实列

| 字段 | 中文母表 | 英文练习 | 日文练习 |
| --- | --- | --- | --- |
| 商品 | 带盖桌面收纳盒 | Desk organizer with lid | ふた付きデスク収納ボックス |
| 结构 | 可拆隔板 | Removable divider | 取り外し可能な仕切り |
| 外尺寸 | 长220×宽150×高120 mm | External size: L220 × W150 × H120 mm | 外寸：長さ220 × 幅150 × 高さ120 mm |
| 发货 | 盒体1、盖子1、隔板1 | Box ×1, lid ×1, divider ×1 | 本体1点、ふた1点、仕切り1点 |

这里是虚构DN01的填写示范，不是已审定商业译稿。正式使用时让熟悉目标语言与类目的人复核自然表达、术语和准确事实。使用[P16英文](https://wangge-dev.github.io/ai-visual-creation-handbook/prompts/P16)或[P17日文](https://wangge-dev.github.io/ai-visual-creation-handbook/prompts/P17)，分别输出译文、回译和需要确认的词。

## 第2步：尺寸计算单独处理

国际英寸与毫米的换算是1 in = 25.4 mm。DN01外尺寸换算并四舍五入到两位：220 mm约8.66 in，150 mm约5.91 in，120 mm约4.72 in。[NIST长度单位说明](https://www.nist.gov/pml/owm/si-units-length)。

保留原值、公式、舍入位数和长宽高标签，使用[P18](https://wangge-dev.github.io/ai-visual-creation-handbook/prompts/P18)。英寸近似值不代替原始测量；不同品牌服装的S/M/L不能仅凭这条公式互换。

## 第3步：准确文字与版式

短标签需要图中呈现时，先排一份可编辑文字稿。长句可以放网页文本区；日文换行不拆关键术语，英文避免因为缩小字号而读不清。模型输出的文字逐字对照，不因整体视觉好看就跳过。

用主题文本／PS／Krita独立文字层排版，保留语言版本。包装原文若需改成另一个语言版本，先确认真实包装是否存在该版本；不能为了本地化改造真实商品标识。

## 第4步：每项声明找依据

“ABS”只说明练习材质，不推出食品级、无毒或可回收。“可拆隔板”不推出可承重或耐温。场景标题是创作表达，数值和功能仍回到事实表。最终交付对照表、准确文字和未确认项，不自动承诺翻译或平台合规完全通过。

# 跨境画布：设计、节点与图层怎样衔接

一个跨境项目可以用三类画布分工：设计画布组织资料与方向，节点工作流复用图像处理，图层软件完成真实主体与准确文字。先按任务选择，不要求每个项目全套软件都使用。

## 第1步：在设计画布安排项目

放入真实商品图、事实表、渠道矩阵和语言稿。建立素材、任务、候选、通过、返工与交付六区。每个任务卡显示SKU、市场、位置、准确文字、参考图角色和结果状态，使用[P08](https://wangge-dev.github.io/ai-visual-creation-handbook/prompts/P08)组织。

Lovart／TapNow的实际按钮、节点连接和导出能力按当前入口确认。画布中画出了流程箭头，只能说明计划关联；实际跑过的步骤再标完成。

## 第2步：用节点复用稳定步骤

先完成真实主体的分割与一张背景合成，再考虑复用。可研究的节点链是：读取实拍→前景／蒙版→生成背景→合成主体→检查→输出。若某个节点会重绘主体，就保留真实商品层作为后续合成依据。

记录具体工作流文件、ComfyUI版本、自定义节点、模型与依赖；断线、缺模型或运行报错分别记录。旧示例工作流可以用于理解结构，不能凭README速度或截图宣称当前环境已跑通。

## 第3步：在图层软件完成交付

将真实主体、背景、接触阴影、准确文案分别存层。英文与日文各自排版，桌面横幅与手机稿重新布局。尺寸图的箭头和单位使用真实参数，不让模型猜。

保存后重新打开检查文字、蒙版和素材链接。PNG只证明平面导出；PSD或Krita文件是否存在、能否打开与编辑单独检查。Codex协作方式见[PS方法](https://wangge-dev.github.io/ai-visual-creation-handbook/workflows/codex-ps)。

## 第4步：回到渠道检查

把同一套事实母版对应到Amazon主图／A+、Shopify产品／横幅、Shopee封面／变体。检查的是具体位置与裁切，不能只看画布总览。把完成和未完成项写回交付清单。

## 平台核对入口

### Amazon图片与A+

Amazon公开图片指导；具体站点、类目和A+模块另核。公开指导的建议、示例与当前类目要求分开；A+像素按实际模块确定，不把普通主图要求套给所有模块。

- 普通商品摄影指导：公开摄影文章建议白底与主体占画面85%或更多；这是指导出处，类目特殊要求仍到Seller Central核对。
- 公开图片FAQ：文章列最长边500—10000像素，以及JPEG、TIFF、PNG、非动画GIF等格式；页面内容已读，不宣称已经完成账户端验证。
- A+设计指导：按模块要求安排图文；公开指南提到图像不大于2MB并强调手机文字可读。各模块实际槽位像素、可用功能以编辑器为准。

[Amazon商品摄影指导（文章发布于2024-12-04）](https://sell.amazon.com/blog/product-photos) · [Amazon A+设计指导（文章发布于2025-09-24）](https://sell.amazon.com/blog/a-plus-content-design-guide) · [Seller Central当前站点帮助入口](https://sellercentral.amazon.com/help/hub)

### Shopify产品媒体、主题图片与alt text

产品／集合媒体、主题通用图片与准确文字分别核对。产品媒体文档与通用上传文档列出不同像素限制；按上传位置使用，主题裁切仍需实际预览。

- 产品／集合图片：当前该文档列最大5000×5000像素或25MP，文件小于20MB；2048×2048方图是展示建议，非所有区块强制尺寸。
- 通用图片上传：当前该文档在上传限制段列20MP与20MB，并注明产品图片有不同限制；不要把两份说明合并成同一规则。
- alt text：官方说明列上限512字符，建议125字符或更少；描述实际图片内容，不堆关键词。

[产品媒体类型](https://help.shopify.com/en/manual/products/product-media/product-media-types) · [通用图片上传](https://help.shopify.com/en/manual/online-store/images/theme-images) · [媒体alt text](https://help.shopify.com/en/manual/products/product-media/add-alt-text)

### Shopee SG商品页图片指导

新加坡公开商品页指导；其他市场、Mall及后台限制另核。以可读取的SG官方指导替代无法请求的通用入口。指导建议不自动扩展成全市场统一硬限制，上传数量与体积等仍按当地后台核对。

- 图片建议：该SG页面建议至少1024×1024的1:1方图、清晰实际商品和纯白封面；这是该文档指导，不填成全市场规则。
- 内容建议：指导强调规格、配件、使用与变体信息；图片不应展示未包含在购买中的配件，也应避免水印或干扰图形。
- 待核范围：实际文件体积、上传张数、店铺类型与其他市场要求未在本轮后台验证；不根据旧Mall PDF补齐。
