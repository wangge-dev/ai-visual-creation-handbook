## 目录组织原则

1. **按作品和任务分类。** “主图、品牌海报、知识卡片”是稳定入口；具体工具与模型放在教程的实现路径和资料卡中。
2. **通用方法集中维护。** 抠图、蒙版、参考图角色、系列一致性、文字检查集中讲，再链接到电商等专题。
3. **提示词方法与提示词库分开。** 第02章教写法，第13章提供完整模板；应用专题关联对应模板与案例。
4. **三类画布分别展开。** 第11章讲操作与组合，第03章放电商完整流程；Codex操作PS在第12章单独讲清。
5. **案例与资源只存一份。** 同一案例可进入电商、品牌、画布等目录，引用同一份素材、过程和源文件。

## 建设顺序建议

- **第一步，定目录：** 确认上述四组、14章与三级目录，明确现有内容各自归属。
- **第二步，补共用基础：** 优先补齐00—02，统一每篇教程的输入、步骤、完整提示词、输出与检查项。
- **第三步，分专题建设：** 电商投入最多；品牌、内容、人物、信息图与视频同步建立基础案例，摄影空间和插画逐步补齐。
- **第四步，串联制作路径：** 把画布、节点、图层、Codex与批量流程接入具体专题，补齐提示词、案例与仓库导航。

准备一张清晰素材、一个明确用途、目标比例和准确文案。首次练习可以用自己拍摄的物体或虚构品牌；商品照片承担外观依据，参考图承担风格或布局依据。

## 操作顺序

1. 写一句交付目标，例如“为真实收纳盒做一张书桌场景图，无文字，3:4”。
2. 标明每张输入图的角色；列必须保留的外观与允许变化的背景。
3. 选择工具时确认实际支持参考图、局部编辑、尺寸和导出格式；在当前入口核对，不根据模型名字推断。
4. 使用[P01商品场景模板](https://wangge-dev.github.io/ai-visual-creation-handbook/prompts/P01)先做一张。主体容易漂移时，改为生成背景后合成真实主体。
5. 对照原素材检查形状、颜色、部件、配件、文字和边缘。一次只改一个关键问题。
6. 保存原素材、实际提示词、结果和修改说明，检查实际像素与文件格式。

## 怎样判断完成

“图看起来不错”还不足以交付。商品身份、内容准确、可读文字、目标裁切和可打开文件都满足任务，才算这一张可用。没有运行结果时，只能报告方案或模板完成。

# 参考图与文件角色

多图输入之前，先做素材清单。图1是真实对象，图2只参考布局，图3只参考色彩，这样比“照着做”更容易定位错误。

| 输入 | 可借用的内容 | 需要保护的内容 |
| --- | --- | --- |
| 商品实拍 | 可见外观与包装 | 形状、部件、颜色、准确标识 |
| 竞品或风格图 | 场景、光线、留白关系 | 不挪用其商品、Logo、参数 |
| 人物参考 | 已获授权的可见特征 | 不凭空补未提供身份与经历 |
| 文案与表格 | 已确认文字与数值 | 不生成额外功效、比例或因果 |

修改时另列“可改区域”和“保护区域”。提示词中的“其余不变”不能证明像素真的未变；需要精确保留时使用蒙版与图层，把原主体留在独立层，再检查修改边界。

如果照片看不清背面、接口或小字，先补素材。推测的结构可以作为概念草图，不能作为商品实物图。局部编辑见[P06](https://wangge-dev.github.io/ai-visual-creation-handbook/prompts/P06)。

证据状态：方法已整理，未执行图像任务。

# 完整提示词怎么写

一条可执行任务词由“任务、输入身份、必须保持、允许修改、画面安排、准确文字、实际输出与检查”组成。模型参数和网站按钮放在工具适配说明中，不混成永远有效的咒语。

## 从短词变成任务

“高级感商品图”缺主体依据、使用位置和结果要求。先填清真实商品图、已核实事实、背景与光线、留白位置、比例和文字，再套用[P01](https://wangge-dev.github.io/ai-visual-creation-handbook/prompts/P01)。需要一套图时先规划各张职责，逐张完成，而不是把十个目标压到一个生成请求里。

分析、策划、生图、修图、排版、批量执行应分开写。例如先从事实表规划卖点，再生成背景，再在图层软件排准确文字。没有生图能力的工具可以输出方案，但不能把文字描述当成已生成图片。

## 失败后怎么改

记录上一版完整提示词和结果；定位是主体漂移、构图、文字还是光影问题。只修改对应条件，保留其他变量比较。中文文案先逐字确认，再根据市场语言本地化；译文检查由熟悉目标语言的人或独立复核步骤完成。

# 商品事实与素材简报

出图前先把商品事实和营销想法分开。照片是外观依据，规格来自已确认记录；不要从照片推测尺寸、功效、认证或内部结构。

| 字段 | 填写方式 |
| --- | --- |
| SKU与变体 | 每个颜色／规格对应原照片和明确ID |
| 可见外观 | 形状、材质表现、部件、包装与标识 |
| 已核实参数 | 数值、单位、来源；缺失写未知 |
| 发货内容 | 商品、配件、数量；道具另列 |
| 买家任务 | 在什么场景解决什么问题 |
| 用途与语言 | 主图／副图／详情／A+／广告，站点与语言 |
| 准确文案 | 审定文字；无依据的功效不写入 |

输出一份事实表、一份素材索引和一份图片职责表，再开始套图。鞋类尤其要区分鞋型、鞋面材质、鞋底、系带与尺码变体；未拍摄角度先补拍。

可参考鞋类业务Skill的分工方法，但资料清单和提示词编排不证明仓库已提供生成引擎。当前资源卡说明已读范围及缺失条件。

# 从单图到一套商品图

以真实商品图和事实表为输入，先分配图片职责，再安排风格一致性。一套图片的数量按渠道和商品任务确定，下面的“1＋5”是练习结构。

| 图片 | 解决的问题 | 必须核对 |
| --- | --- | --- |
| 1 主图 | 买家一眼识别商品 | 主体真实、发货内容、渠道要求 |
| 2 场景 | 在哪里使用 | 大小关系、道具是否误导 |
| 3 细节 | 材质与关键结构 | 原图依据、没有补假结构 |
| 4 尺寸 | 是否合适 | 真实参数、单位、标注 |
| 5 使用 | 怎么操作 | 顺序和动作符合实际 |
| 6 信任信息 | 为什么可信 | 证明材料与准确文案 |

## 制作步骤

1. 按[商品简报](https://wangge-dev.github.io/ai-visual-creation-handbook/ecommerce/product-brief)整理SKU与实拍。
2. 为每张图写一张任务卡，共用主体、色彩与字体，分别写构图和准确文字。
3. 使用[P01](https://wangge-dev.github.io/ai-visual-creation-handbook/prompts/P01)先完成场景图，检查商品身份后再扩展。
4. 细节和尺寸图以真实照片与数据为底，准确文字用图层排版；需要改一处时使用[P06](https://wangge-dev.github.io/ai-visual-creation-handbook/prompts/P06)。
5. 在[三类画布](https://wangge-dev.github.io/ai-visual-creation-handbook/workflows/canvases)中分离候选、通过和返工版本。
6. 逐图检查，再检查整套一致性；导出文件名包含SKU、用途、语言与版本。

图像模型生成的细节放大不等于真实微观结构。证据图、检测报告和认证标识使用真实授权原件，不生成替代。

## 先做模块简报

| 模块 | 输入 | 交付 |
| --- | --- | --- |
| 开头 | 商品、核心使用任务 | 主体＋一句准确价值说明 |
| 场景 | 获准场景、真实尺寸 | 背景与真实主体合成 |
| 细节 | 局部实拍、材质事实 | 特写＋有来源的标注 |
| 规格 | 已确认参数与配件表 | 可读表格／示意图 |
| 使用 | 实际操作步骤 | 顺序图与准确提示 |

先输出逐屏文案和图片清单，核对后逐屏制作。长页拼接前检查裁切、字号、边缘和模块重复。A+按当前站点、账户和所选模块的实际输入限制规划，不把旧模板宽度当通用规定。

提交时提供整页预览、分模块图片、准确文字与源文件状态。未创建PSD、无法编辑或未实际导入的平台内容要分别说明。跨境本地化见[跨境交付](https://wangge-dev.github.io/ai-visual-creation-handbook/ecommerce/cross-border)。

# 跨境电商出图与本地化

先确定市场、站点、位置与模块，再确定语言、比例和文件。Amazon主图、商品副图、A+，Shopify主题的商品媒体与横幅，Shopee各市场入口承担不同任务。平台规则集中在[资料库](https://wangge-dev.github.io/ai-visual-creation-handbook/resources/)，具体数值以当前官方页面、登录后的模块提示和实际预览为准。

## 跨境制作顺序

1. 建“渠道×市场×图片位置×SKU”清单。每行保存当前要求的出处与核对时间。
2. 固定商品身份和发货内容；场景可以本地化，商品尺寸、结构与功能不能随市场改变。
3. 根据真实数据转换单位，保留计算依据。标题、标签、警示和包装文字分别处理，不直接让整图模型改所有小字。
4. 让目标语言复核者检查自然表达、数值、使用说明及当地语境。缺依据的合规或认证声明留空待补。
5. 先做一种语言的母版和一张样图，检查后按SKU扩展；不同位置单独排版裁切，不只缩放同一张长图。
6. 在实际商品页／编辑器预览桌面与手机，查看首屏裁切、文字可读性和图片顺序。

## 最小交付清单

文件命名含市场、语言、SKU、位置和版本；配套事实表、文案对照、规格来源、检查结果和可编辑文件说明。广告图和商品主图分别制作，避免把宣传字样误放到不允许的位置。

这页提供流程方法，尚未在Amazon、Shopify或Shopee后台完成真实上传。首批跨境实操案例列入待补清单，平台变化只修订受影响步骤。

## 借鉴业务Skill时怎么核对

新收录的电商Skill库有跨境本地化与检查脚本，可借鉴市场、语言、尺寸与变体的任务拆分。来源中的区域偏好、尺码对照和平台规格不能直接成为本库规则；先用真实商品参数和当前站点资料复核。准确文字优先独立排版。

脚本入口实际位于shared/scripts或技能目录的scripts下。先核对工作目录、素材相对路径与后端，再试一项任务；本项目尚未运行其生成任务。

# SKU系列与导出检查

每个变体绑定真实照片、规格和文案。不要仅把一个商品图染色就宣称其他SKU真实存在；存在结构差异的变体需要对应素材。

先做一张通过的母版，再按清单替换主体与文字。批量记录每项SKU的输入、提示词、结果、返工原因和导出路径。失败保留原任务ID，先查看是否已生成结果，避免重复提交。

导出时核对实际像素、比例、透明背景、文字、裁切与文件能否打开。源文件单独检查图层、文字可编辑性、嵌入素材与链接丢失情况。给客户的预览JPEG不能替代PSD或节点工作流。

检查通过后再组合图片顺序；未通过项留在返工区，不能混入交付目录。任务组织见[P08](https://wangge-dev.github.io/ai-visual-creation-handbook/prompts/P08)和[批量方法](https://wangge-dev.github.io/ai-visual-creation-handbook/workflows/batch)。

# 三类画布怎么接入电商出图

设计画布组织方向与任务，节点工作流复用处理步骤，图层软件负责准确合成与精修。它们可以组合：先组织商品简报和方案，再批量生成候选背景，最后把真实主体与准确文字合成。

| 画布 | 适合负责什么 | 需要另外检查 |
| --- | --- | --- |
| Lovart／TapNow等设计画布 | 参考、方向、任务和系列版式组织 | 当前入口实际提供的连接、输出与编辑能力 |
| ComfyUI节点 | 输入、生成、抠图、合成、批量的显式流程 | 节点版本、模型、依赖和真实运行结果 |
